# Self-Hosted WordPress With MySQL and Cloudflare Tunnel

This repository runs WordPress, MySQL, and Cloudflare Tunnel with Docker Compose.
WordPress is publicly exposed only through Cloudflare Tunnel. MySQL is isolated on
an internal Docker network and is not published to the host.

## Services

- `wordpress`: WordPress with Apache and PHP.
- `mysql`: MySQL database, isolated on the internal `database` network.
- `cloudflared`: Cloudflare Tunnel client using a dashboard-managed tunnel token.
- `wp-cli`: Optional one-shot bootstrap service for initial WordPress installation.

## Storage

All persistent data is stored under `./site_storage/`:

- `./site_storage/wordpress` -> `/var/www/html`
- `./site_storage/mysql` -> `/var/lib/mysql`

These are bind mounts, not named Docker volumes.

## Prerequisites

- Docker Engine with Docker Compose v2.
- A Cloudflare account with Zero Trust enabled.
- A Cloudflare Tunnel created in the Zero Trust dashboard.
- A public hostname in Cloudflare routed to the tunnel.

## Environment Setup

Create your deployment environment file:

```bash
cp .env.example .env
chmod 600 .env
```

Edit `.env` and replace every placeholder value.

### Required Variables

`CLOUDFLARE_TUNNEL_TOKEN`

The token generated by Cloudflare Zero Trust for the tunnel. The `cloudflared`
service runs only with this token and does not use a local `config.yml`.

`WORDPRESS_SITE_URL`

The public HTTPS URL for the WordPress site, for example:

```text
https://www.example.com
```

This value is used by the optional `wp-cli` bootstrap service.

`WORDPRESS_SITE_TITLE`

The initial WordPress site title used by the optional bootstrap service.

`WORDPRESS_ADMIN_USERNAME`

The initial WordPress administrator username used by the optional bootstrap
service.

`WORDPRESS_ADMIN_PASSWORD`

The initial WordPress administrator password used by the optional bootstrap
service. Use a strong unique password.

`WORDPRESS_ADMIN_EMAIL`

The initial WordPress administrator email address used by the optional bootstrap
service.

`MYSQL_DATABASE`

The MySQL database name created for WordPress.

`MYSQL_USER`

The MySQL application user used by WordPress.

`MYSQL_PASSWORD`

The MySQL application user password. Use a strong unique password.

`MYSQL_ROOT_PASSWORD`

The MySQL root password. Use a strong unique password and do not reuse the
WordPress database user password.

## Cloudflare Zero Trust Routing

In the Cloudflare Zero Trust dashboard, configure the tunnel public hostname to
route to the internal WordPress service:

```text
http://wordpress:80
```

Do not create a local Cloudflare Tunnel `config.yml` for this setup. Ingress is
managed entirely in the Cloudflare dashboard.

## Deploy

Validate the Compose configuration:

```bash
docker compose config
```

Start the main stack:

```bash
docker compose up -d mysql wordpress cloudflared
```

Check service status:

```bash
docker compose ps
```

Follow logs:

```bash
docker compose logs -f mysql wordpress cloudflared
```

## First-Time WordPress Bootstrap

After the main stack is healthy and the tunnel hostname is routed, run:

```bash
docker compose --profile bootstrap up wp-cli
```

This installs WordPress using the `WORDPRESS_SITE_URL`,
`WORDPRESS_SITE_TITLE`, `WORDPRESS_ADMIN_USERNAME`,
`WORDPRESS_ADMIN_PASSWORD`, and `WORDPRESS_ADMIN_EMAIL` values from `.env`.

If WordPress is already installed, the bootstrap service exits without changing
the existing installation.

## Security Notes

- MySQL is attached only to the internal `database` network.
- MySQL exposes port `3306` only to other containers on its Docker network.
- No services publish host ports in `docker-compose.yml`.
- Public access should come through Cloudflare Tunnel only.
- Keep `.env` private and do not commit it.
- Rotate credentials if `.env` is ever exposed.

## Common Operations

Stop the stack:

```bash
docker compose down
```

Restart services:

```bash
docker compose restart
```

Update images:

```bash
docker compose pull
docker compose up -d
```

Back up local persistent data:

```bash
tar -czf site_storage-backup.tar.gz site_storage
```

## Troubleshooting

If WordPress shows database connection errors, check MySQL health and logs:

```bash
docker compose ps mysql
docker compose logs mysql
```

If the public URL does not load, check the Cloudflare Tunnel container logs:

```bash
docker compose logs cloudflared
```

Confirm the Cloudflare dashboard hostname routes to:

```text
http://wordpress:80
```

If assets load over HTTP instead of HTTPS, confirm `WORDPRESS_SITE_URL` uses
`https://` and that Cloudflare is sending `X-Forwarded-Proto: https` or
`CF-Visitor` headers through the tunnel.
